## 实现范围

当前包含基础认证、老人档案、服务目录、预约申请与人工安排、履约、预约专用家属授权、本人绑定、微信登录、四类手工健康测量及独立健康授权，并提供管理后台和移动端页面。求助投递、医疗附件、设备和短信尚未实现；微信入口依赖外部凭据及 HTTPS 配置。

数据库结构以 Flyway 迁移为准：V1 为社区与账号，V2 为老人档案，V3 为服务目录、预约、执行记录、账号绑定和预约授权，V4 为健康记录、不可覆盖版本、独立授权、访问事件和幂等请求。原预约开发方向与[健康模块方案](archive/HEALTH_MODULE_PLAN.md)均已归档，现行行为以接口文档为准。

## 维护约定

- 工程行为以源码、迁移和锁文件为准；契约变更与实现同时提交。
- 规划能力标注状态，不混入已实现接口列表。
- 版本升级更新依赖依据；不在文档中存放凭据或真实个人信息。
- 模块交付完成，或文档被替代、废弃后，移入[归档目录](archive/README.md)并在其中登记；归档文档不作为现行契约。
